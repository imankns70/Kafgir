# انتشار در شبکه‌های اجتماعی

## هدف و محدوده

ماژول انتشار اجتماعی بخشی از Electron Admin است و برای انتشار محتوای فارسی کفگیر در تلگرام، بله و ایتا استفاده می‌شود. این ماژول سیستم کمپین، تحلیل بازاریابی، زمان‌بند مستقل، تولید متن با هوش مصنوعی یا مدیریت کامنت و دایرکت نیست.

Electron از طریق `packages/server-core` به PostgreSQL متصل می‌شود. renderer فقط عملیات تایپ‌شده IPC را فراخوانی می‌کند و به SQL، توکن کانال یا connection string دسترسی ندارد. توکن‌ها در Electron main با Windows DPAPI (`safeStorage`) رمز می‌شوند و فقط ciphertext در `social_channels.credential_ciphertext` نگهداری می‌شود.

## صفحات مدیریت

- `داشبورد انتشار`: خلاصه پیشنهادها، ارسال‌های موفق/ناموفق و خط زمانی امروز.
- `کانال‌ها`: ثبت کانال تلگرام/بله/ایتا، فعال‌سازی و آزمون اتصال.
- `انتشار جدید`: تولید پیش‌نویس از داده واقعی منوی امروز، انتخاب مقصد، متن اختصاصی هر مقصد، پیش‌نمایش و تأیید انتشار.
- `قالب‌های پیام`: متن قابل ویرایش پنج نوع محتوای منوی روز، معرفی غذا، تخفیف، ظرفیت محدود و پیام آزاد.
- `قوانین خودکارسازی`: بازه زمانی، اولویت، فاصله اجرا، سقف روزانه، آستانه داخلی و کانال‌های مقصد.
- `پیشنهادهای انتشار`: پیش‌نمایش، رد یا انتشار پیشنهاد تولیدشده.
- `تاریخچه ارسال`: فیلتر تاریخ، پلتفرم، کانال، نوع، نتیجه، مبدأ و منبع؛ تلاش مجدد فقط برای مقصد ناموفق یا نامشخص.

## حالت‌های اجرا

- `دستی`: هیچ کار خودکاری انجام نمی‌شود.
- `پیشنهاد`: قانون یک پیشنهاد قابل بررسی می‌سازد. حالت پیش‌فرض همه قوانین seed شده است.
- `انتشار خودکار`: پیش‌نویس و ارسال بدون تأیید دستی، تنها زمانی که Electron باز است و کاربر Owner وارد شده است.

در حال حاضر Worker مستقل وجود ندارد. ارزیابی خودکار هر ۶۰ ثانیه در Electron main انجام می‌شود. سرویس‌ها framework-independent هستند تا اگر بعداً Worker اضافه شد همان rule engine و publication service دوباره استفاده شود.

## داده واقعی و حریم ظرفیت

پیش‌نویس منو، معرفی غذا، قیمت و تخفیف فقط از PostgreSQL و منوی واقعی همان روز ساخته می‌شود. UI نمی‌تواند قیمت یا تخفیف ساختگی برای automation ارسال کند.

موجودی و ظرفیت دقیق اطلاعات داخلی هستند. قالب عمومی اجازه استفاده از متغیرهای `remainingCapacity`، `initialCapacity`، `capacity`، `soldQuantity`، `remainingPercentage` یا `productionQuantity` را نمی‌دهد. محتوای «ظرفیت محدود» فقط حالت معنایی `Limited` و عبارت‌هایی مانند «ظرفیت محدود» یا «رو به اتمام» را منتشر می‌کند؛ عدد دقیق پرس، درصد یا تولید وارد متن عمومی نمی‌شود.

## جلوگیری از تکرار و ارسال نامطمئن

- هر target دارای idempotency key یکتا است.
- claim مقصد با `FOR UPDATE SKIP LOCKED` انجام می‌شود.
- موفقیت هر مقصد جدا ثبت می‌شود؛ شکست یک کانال باعث ارسال دوباره به مقصد موفق نمی‌شود.
- مقصد ناموفق حداکثر سه تلاش دارد و retry فقط همان مقصد را هدف می‌گیرد.
- مقصدی که هنگام crash در وضعیت `Publishing` مانده باشد به `Unknown` می‌رود و خودکار دوباره ارسال نمی‌شود؛ چون ممکن است شبکه پیام را دریافت کرده ولی پاسخ نرسیده باشد.
- پیشنهاد ردشده با همان rule/source/date دوباره ساخته نمی‌شود.
- advisory lock، cooldown سراسری و rule-level، سقف روزانه، سقف هر غذا و quiet hours هم‌زمان اعمال می‌شوند.

## اتصال‌دهنده‌ها

- Telegram از Bot API و `sendMessage`/`sendPhoto` استفاده می‌کند.
- Bale از API سازگار با Bot API استفاده می‌کند.
- Eitaa از EitaaYar استفاده می‌کند. چون دکمه inline و ارسال media در این مسیر تضمین یکسانی ندارند، تصویر و لینک سفارش در متن افزوده می‌شود. آزمون اتصال بدون ارسال برای این provider با وضعیت «پشتیبانی نمی‌شود» گزارش می‌شود.

توکن هر کانال باید اجازه ارسال به مقصد ثبت‌شده را داشته باشد. هر سه اتصال‌دهنده timeout محدود دارند و هیچ توکن یا متن credential در log نوشته نمی‌شود.

## قالب‌ها و نمونه‌ها

متغیرهای مجاز قالب‌ها عبارت‌اند از: `foodName`، `description`، `price`، `originalPrice`، `discountPrice`، `menuItems`، `orderUrl` و `customText`.

```text
منوی امروز کفگیر
{{menuItems}}
ثبت سفارش: {{orderUrl}}
```

نمونه ظرفیت محدود امن:

```text
{{foodName}} رو به اتمام است.
برای سفارش امروز زودتر اقدام کنید: {{orderUrl}}
```

## عملیات و عیب‌یابی

1. migration `0017_social_publishing.sql` را اجرا کنید.
2. با نقش Owner وارد Electron شوید.
3. کانال و token را در صفحه کانال‌ها ثبت و «آزمون اتصال» را اجرا کنید.
4. در انتشار جدید ابتدا پیش‌نویس تولید کنید، متن نهایی هر پلتفرم را در tab همان مقصد ببینید و سپس تأیید کنید.
5. نتیجه هر مقصد را در تاریخچه بررسی کنید. برای Failed/Unknown فقط retry همان مقصد در دسترس است.

```text
npm run social:verify --workspace @kafgir/web
npm run lint
npm test
npm run build
```

`social:verify` قالب‌ها، قوانین seed شده، تنظیمات و پیش‌نویس‌های قابل ساخت از داده واقعی دیتابیس فعلی را بررسی می‌کند؛ هیچ پیام شبکه‌ای ارسال نمی‌کند.

## محدودیت‌های نسخه اول

- انتشار خودکار به بازبودن Electron وابسته است.
- credential رمز‌شده با DPAPI فقط روی همان حساب Windows قابل رمزگشایی است؛ Worker آینده باید secret store مستقل داشته باشد.
- اتصال واقعی به Telegram/Bale/Eitaa به credential و کانال واقعی نیاز دارد و در build/test آفلاین شبیه‌سازی می‌شود.
- این نسخه آمار تعامل، کمپین، پاسخ به پیام، AI copywriting و scheduler مستقل ندارد.
